## 3. Your issues, one by one

### 3.1 Connections → GitHub says "Coming soon"
- **Cause:** the GitHub row only shows **Connect** when the server has a GitHub OAuth app configured (`backend/koe/connections.py:235`, `github_ready()` needs `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET`). Render doesn't have them, so the row falls back to "Coming soon" (`frontend/src/settings/Connections.tsx:147`).
- **Fix (you, about 5 minutes, no code):**
  1. On GitHub, go to Settings → Developer settings → OAuth Apps → **New OAuth App**.
  2. Homepage `https://koe-pi.vercel.app`, callback `https://koe-pi.vercel.app/auth/github/callback`.
  3. Copy the Client ID and generate a secret.
  4. On Render → Environment, add `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET`, then redeploy.
- **Fix (me):** change "Coming soon" to "Not set up on the server" when it's a configuration problem, so it doesn't look like a missing feature.
- **Meanwhile:** the GitHub *tools* still work through the server-wide `GITHUB_TOKEN`. That's why "How much did I ship?" answered.

### 3.2 Connections → Notion says "Coming soon" but Notion works
- **Cause:** both are true. Notion works through the **server-wide** `NOTION_TOKEN` + `NOTION_DATABASE_ID` on Render. That's why the Notion page and tools work. **Per-person** Notion connect (OAuth, so each user picks their own pages) was never built: `CONNECT` in `Connections.tsx:20` only has Google and GitHub.
- **Fix (me, small):** while the server token is in use, the row should say **"Connected (workspace: <name>) · server key"** instead of "Coming soon".
- **Fix (me, bigger, needs your OK):** real Notion OAuth connect. You'd create a public Notion integration, and it needs a new provider flow in `auth.py`. Only worth building if friends will use Koe with their own Notion.

### 3.6 Saying "yes" doesn't confirm the Google Sheet update
Your Activity screenshot shows the **button** approval worked (10:16, "Action executed"). The **voice** path is the broken one. It has three causes, all in the backend:
1. **Strict exact-phrase list.** `agent.confirmation()` (`backend/koe/agent.py:353`) accepts only the *entire* utterance being one of `yes`, `yes please`, `confirm`, `approve`, `go ahead`, `yes go ahead`. Gemini's transcript of natural speech is often "Yeah", "Yes, do it", "Okay", "Sure", "Haan", or "Yes confirm it", and all of those are ignored.
2. **Timing guard.** The voice "yes" only counts after Koe has finished speaking the proposal (`approval_ready` is set on `turn_complete`, `backend/koe/voice_call.py:223`). A "yes" said while she's still reading it out is dropped.
3. **Misleading reply.** When the "yes" isn't caught, the text goes to the model as normal chat. The model can't approve anything, but it can *say* something that sounds like it did.
- **Fix (me):**
  - Normalise and accept a short list of affirmatives and negatives (yeah, yep, sure, ok/okay, do it, confirm it, haan/haa, nahi, …) but only when the whole utterance is short (≤ 4 words), so "yes but change the time" never approves.
  - Accept a "yes" that lands in the same turn the card appears.
  - Make the model say *"I didn't catch a clear yes. Say 'yes' or tap Confirm."* instead of claiming success.
  - Add tests for each phrase.

### 3.7 Google Sheets shows only a duration, not a from–to time
- **Cause:** that's the current design. The timesheet columns are `Date, Client, Hours, Note, Koe action ID` (`backend/koe/tools/sheets.py:17`), and `sheets_log_hours` takes only `date, client, hours, note`.
- **Fix (me, changes a tool, so CLAUDE.md says I ask first):** add optional **Start** and **End** (HH:MM, Asia/Kolkata).
  - "Log Acme 2 to 4:30 pm" fills Start/End and computes Hours = 2.5.
  - "Log 2 hours" still works.
  - Existing sheets get the two columns through the existing add-column approval.
  - "Create my timesheet" includes them from the start.

### 3.8 Dashboard "Approvals" and "Waiting for your review" look empty or missing
Neither panel is broken, but both are confusing:
- **Approvals** shows only proposals **pending right now**. Once you confirm or cancel, they leave the panel and appear only in Activity. That's why it says "Nothing waiting on you" after your tests.
- **Waiting for your review** uses the GitHub search `review-requested:@me` (`backend/koe/tools/github.py:91`). It lists PRs where *someone else asked you* to review. On solo repos it's always empty.
- **Fix (me):**
  - Approvals gets a small **Recent decisions** list (the last 5, with ✓ executed / ✗ cancelled / expired), so it's never a blank box.
  - The review panel's empty state says what it's waiting for, and offers **Your open PRs** instead.
  - Tiles shrink to their content instead of standing as tall empty boxes (your screenshot 4).

## 4. Approving other people: how it works now, and an Owner page

**How it works today (once Render is redeployed):**
1. Your account is the **owner** because its email equals `KOE_ADMIN_EMAIL` on Render.
2. Open **Settings → People** (only you see it). Under **Invite someone**, type their Gmail and add it.
3. Send them the link `https://koe-pi.vercel.app` yourself. Koe doesn't email anyone.
4. They click **Continue with Google** with *that* Gmail and they're in. Anyone else sees "not invited".
5. **Remove** deletes the invite and signs them out everywhere.
6. Google side: while your Google OAuth app is in **Testing** mode, each friend also has to be added as a **test user** in Google Cloud → OAuth consent screen. Otherwise Google blocks them before Koe ever sees them. (Max 100 test users; no verification needed.)

So it's an **invite list**, not an approval queue. You approve people *before* they try, by adding their email.

**Proposed: a dedicated Owner page (`/owner`), owner-only:**
- **Access requests.** A not-invited person who signs in sees "Request access" instead of a dead end. Their request appears on `/owner` with **Approve / Deny**, and you get a push notification.
- **People.** Everyone invited or joined, when they last signed in, and **Remove**.
- **Usage.** Gemini calls per person today against the shared free limit (`usage.py` already counts them).
- **Setup checklist.** A live ✓/✗ for every server setting: Google OAuth, GitHub OAuth, Notion, Spotify, VAPID, Neon migrations, `KOE_ADMIN_EMAIL`. This would have shown today's problems at a glance.
- **Reminder:** "Add <email> as a Google test user", with a link, after each approval.

People would move out of Settings into this page. Backend: one `access_requests` table (migration 008) + 3 routes. Frontend: one page.
